# Voice Button 1.06 — physical-phone diagnostic re-review

On October 19, the Ulefone reported version 1.05 with 156 local recording sessions, approximately 10.43 GB of local recording storage, and 5.08 GB of finalized MP3 bytes durably acknowledged by Jetson. Zero MP3 bytes were pending and the receiver was healthy. The private live PCM mirror was not paired: `paired=false`, `remote_durable=0`, `local_durable=1663360`. These raw bytes are not Jetson-backed; no private access token was present on the phone. Legacy post-recording MP3 backup continues to work, but **the live microphone cannot be protected remotely without explicit server pairing**. This is intentional private-microphone authorization, not a reason to enable anonymous raw audio uploads.

Actual version 1.05 phone trace: service startup took 2,154 ms (1,641 ms store initialization, 500 ms manifest scan). Start-request preflight took 1–2 ms; one new session's durable metadata took 14 ms and another 357 ms; Bluetooth recorder activation took 1,279–1,327 ms. These substantially improve the previous measured 17.6-second startup and 5.3-second Start latency. Further speed claims must be based on the physical phone rather than automated emulator runs. The receiver reports 172 completed transcriptions, including the newly finished MP3.

The 1.05 support diagnostics also showed `live_pcm.active=true` after the microphone had stopped. That field was misleading: it described the low-priority raw-upload worker, which can remain available to drain queued raw audio, not actual microphone capture. Version 1.06 marks capture inactive upon confirmed recorder stop, without discarding pending PCM prefixes. When there is no pairing key, the worker waits on a signal instead of waking every second to repeat the same check. Saving/refreshing credentials signals the worker promptly. Unit tests cover an inactive microphone with pending raw backup and correct behavior across recording switches.

The earlier `last_failure=InterruptedIOException` arose when the foreground microphone deliberately cancelled the old uploader's private metadata calls. This is expected handoff, not a lost recording, and the existing diagnostic falsely preserved it as an error even after confirmed MP3 transfer. Version 1.06 no longer persists cancellation exceptions as transfer failures in folder/metadata or part-upload handlers. A subsequent successful reconciliation clears an obsolete failure, while genuine outstanding metadata problems remain visible. Status-only metadata queries no longer falsely advance the durable-byte progress timestamp.

Privacy and acceptance limit: remote live PCM still requires the owner to provision the private recording server access token through More → Recording server access on the handset. Do not embed that secret into distributed APKs, public pages, Git commits, or support diagnostics. Do not claim the live mirror succeeded merely because post-recording MP3 backup reached 100 percent. The new APK must be installed on the physical phone to verify the corrected flags and measured timings.
