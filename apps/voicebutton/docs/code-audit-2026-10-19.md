# Voice Button source audit — 2026-10-19

The Android service has a confirmed initialization error. During its first idle snapshot, it used to stamp lastLocalBytesScanElapsedMs without actually measuring storage. The cache initially contains zero bytes. As a result, a ready app could report local_bytes=0 despite hundreds of recorded files. Corrected: when no successful scan exists, scanStore.localBytes() runs on the background status executor and only then records the success time. Periodic refresh remains throttled to thirty seconds. No microphone capture thread or UI path recursively scans files.

The Android app startup is asynchronous: Application initializes diagnostics and upload scheduling, RecordingService enters STARTING and creates its stores/manifest state on serviceExecutor, and statusExecutor later reconciles snapshots. Its lifecycle prioritizes durable PCM journaling and stops on explicit Exit with a persistent upload gate. ReliableUploader applies durable server byte acknowledgements before marking chunks remote. A health or READY display alone does not exercise microphone capture, HTTP part delivery, service restart, UI rendering, and final transcription together.

Jetson full_duplex_server uses DurableAudioV2 for fsynced and revisioned audio storage, with local final STT work managed independently. Authorization tests verify protected folder metadata and the temporary compatibility rules for legacy writes. The receiver initializes DurableAudioV2 lazily on a first audio API request; that initialization synchronously reconciles existing exports and can delay its first request after restart. This is an unmeasured cold-start risk rather than a confirmed fault. The scanner periodically walks all manifests, another possible scaling cost. Do not rewrite this data path without a profile or new regression tests.

On Jetson the eleven Voice Button access tests and nineteen durable audio tests passed. On Nitro the original version 1.00 Android app's one hundred ten unit cases, debug APK, lint, and instrumentation APK compilation passed. After correcting the local scan, the complete unit suite and APK assembly passed. An actual physical phone test of version 1.01 and a fresh multilingual recording through final transcript remain required; existing manifests cannot prove these. No user recording data or live server configuration was modified during this audit.

## Follow-up findings and repairs in version 1.02

The background uploader originally handled an HTTP 401 or 403 returned by a private folder-create request as just another folder warning, and repeated the same request every second. With multiple pending folders it also issued one failure per folder in each loop iteration. This can fill phone and server diagnostics and waste CPU even when audio itself has completed. The revised worker separates metadata write eligibility from actual audio transfer, suppresses repeated denied writes until credentials change or an explicit retry creates a new worker, throttles transient write failures to at least thirty seconds, and exits background-only workers when the remaining work is not actionable. A private-folder failure never quarantines unrelated locally saved recordings.

The old foreground uploader scanned the entire local manifest list every roughly one-and-a-half seconds even while idle. It now waits up to thirty seconds in the absence of work, with a monotonic wake generation ensuring a signal arriving between scanning and sleeping is not lost. Audio transfer readiness is prioritized and retains short waits during active uploads. New tests cover the private metadata read/write authorization gates and retry deadlines.

Most importantly, current microphone capture uses a durable PCM journal and deliberately suspends MP3 conversion and network upload until pause or finish. This contradicts older requirements that called for immediate live replication. The main screen no longer implies that newly captured PCM has reached Jetson. Safely restoring real-time redundancy and partial transcripts requires a separate profiled streaming architecture, not activating the current heavyweight Whisper service for every tiny capture block. This remains an unresolved requirement, not a claimed completed repair.

After these changes the Android unit suite passed 110 tests and the networking suite passed 41 tests without failures. Debug APK assembly, Android instrumentation APK compilation and lint succeeded. Version 1.02 is an in-place update using the existing signing certificate. The installed physical handset still requires validation; no user data was deleted.
