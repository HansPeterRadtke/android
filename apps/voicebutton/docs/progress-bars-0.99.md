# Voice Button version 0.99 — restore truthful progress bars

October 19, 2026. The version 0.98 simplification mistakenly hid the upload and transcription progress bars despite the requirement to show progress. Version 0.99 restores the primary indicators and separates measured progress from work phase.

The fixed panel below the toolbar contains the overall backup label and determinate byte-acknowledgement bar, then the overall transcription label and server-verified completion bar. Both use existing stable view IDs. A pending/current recording has a named per-file backup progress row, using verified segment sizes and partial server offsets. The current server transcription has a named per-file frame progress row when the authenticated status endpoint provides one. No dynamic per-file queue is created on the recorder overview when it would dominate the microphone controls.

The overall upload denominator includes all encoded MP3 chunks represented by local manifests, including already-committed recordings and closed chunks from an active recording. This avoids disappearing bars or resetting to zero after a completed recording is removed from the pending set. The denominator increases when a *new* chunk becomes available, so the current-known-byte percentage can decrease legitimately during continuous recording; the label explicitly states that the recording adds chunks. No percent is fabricated for not-yet-encoded audio. Finished files still require final server commit after byte-level confirmation, which has a distinct label. Explicit Pause/Exit and server retry states are clearly identified. Partial bytes count only after durable server acknowledgement; the active in-memory durable floor is included only if session ID, chunk sequence, expected size and active upload phase all match.

The server's overall transcription percentage and completed/total counts are shown only after a verified status response. On a refresh error, the last known figures are frozen and labeled with elapsed age; without any result the interface states that the server status is unavailable and does not display a made-up percentage. Per-file transcription uses server frame counters only; model initialization is indeterminate only while current. Privacy-redacted server responses do not invent a current-file percentage.

Testing: pure Java unit regressions cover active and finished recordings, matching/mismatched live chunk acknowledgements, partial confirmations, missing MP3 totals, commit distinction, and truthful labels. Instrumented UI expectations require an overall backup bar and a transcription status label to be visible in the idle recorder. Build and lint, Android instrumentation compilation, APK signing and an in-place update must be checked before distribution. The real phone remains a distinct acceptance step.

Compact landscape places both overall bars in the right-hand overview column. The screenshot regression fixture verifies a non-empty server transcript backlog and requires both backup and transcription bars to have nonzero height and remain visible in normal layouts.

## Toolbar correction, October nineteenth

The visible Exit button was introduced by the October eighteenth repair, not by a user-authored Voice Button recording or an infrastructure GUI rule. It wrongly competed with Finish, More and the progress indicators in a small recorder toolbar. It is removed from the prominent toolbar. Standard Android Back and the existing More menu Exit action continue to safely close, preserving the prior data-protection and explicit-upload-stop behavior. The instrumented UI and exit-action tests now use Back and assert no prominent Exit control.
